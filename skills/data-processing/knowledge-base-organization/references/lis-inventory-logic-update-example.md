# LIS 库存逻辑修改示例

## 背景
用户要求修改LIS库存逻辑，为CRIN系列增加排除索引"54P"。

## 执行步骤

### 1. 检索现有逻辑
- 使用 `mcp_LLM_WIKI_search_wiki` 搜索 "LIS 库存逻辑"
- 读取原始文件 `docs/LIS 库存逻辑.txt`
- 确认CRIN系列规则（规则1、2、11、12）

### 2. 修改原始文件
- 备份：`cp file file.bak`
- 使用 `patch` 工具修改4条规则：
  - 规则1：`a.index <> '1C4'` → `a.index NOT IN ('1C4', '54P')`
  - 规则2：合并排除条件为 `a.index NOT IN ('-R00', '1C4', '54P')`
  - 规则11/12：`a.index <> '1C4'` → `a.index NOT IN ('1C4', '54P')`

### 3. 同步到 LLM-Wiki
- `mcp_LLM_WIKI_ingest_file` 重新 ingest
- `mcp_LLM_WIKI_approve_diff` 审核通过

### 4. 更新相关 Wiki 页面
- 更新 `i4-platform/lis物料分类规则.md`：
  - 修改CRIN系列描述
  - 更新排除条件说明
  - 添加修改记录章节

### 5. 记录修改
- 在文档中添加修改记录章节
- 使用 `mem0_add` 存储修改摘要

## 用户反馈
- 用户两次说"重试"，要求加快节奏减少分析
- 用户要求记录修改到Mem0方便回溯
- 用户问"我咋改" — 需要区分文档层（agent已完成）和系统层（用户需手动操作）

## 经验教训
1. 用户说"重试"时应跳过详细分析，直接执行
2. 修改记录必须包含时间、内容、影响范围、同步状态
3. 同时更新原始文件和引用该文件的Wiki页面
4. 使用Mem0存储修改摘要，方便快速检索
5. **文档层 ≠ 系统层**：修改知识库文档后，必须告知用户实际系统（数据库表/存储过程）也需要同步修改
