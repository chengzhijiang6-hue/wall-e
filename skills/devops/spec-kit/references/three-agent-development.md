# 三 Agent 协作开发模式

## 触发条件

用户要求"采用项目开发的逻辑讨论并实施"、"头脑风暴"、"多个角度分析"时使用。

## 角色定义

| Agent | 职责 | 工具集 |
|-------|------|--------|
| **汇总 Agent (Coordinator)** | 整合成果、生成报告、维护文档、协调沟通 | file, session_search, memory |
| **监督 Agent (Supervisor)** | 监控进度、检测异常、审查代码、验证验收标准 | terminal, file, search |
| **实施 Agent (Implementer)** | 执行编码、部署服务、编写测试、修复问题 | terminal, file, execute_code |

## 工作流程

```
用户需求 → 汇总 Agent 分配任务
                ↓
    ┌───────────┼───────────┐
    ↓           ↓           ↓
 监督 Agent  实施 Agent  汇总 Agent
 (审查)      (执行)      (记录)
    └───────────┼───────────┘
                ↓
          任务完成 → 下一任务
```

## 执行模式

### Phase 级执行
```
1. 汇总 Agent 分析需求，制定计划
2. 实施 Agent 执行 Phase N 的所有任务
3. 监督 Agent 审查代码质量和规范
4. 汇总 Agent 记录进度，进入 Phase N+1
```

### 头脑风暴模式（技术选型）
```
1. 汇总 Agent 定义分析维度
2. 派发 3 个子代理，分别站在不同立场分析
3. 汇总 Agent 整合三方观点
4. 给出综合建议
```

## 通信协议

任务通过 `delegate_task` 派发，每个子代理需要：
- 明确的任务目标
- 相关的上下文信息
- 指定的工具集

## 注意事项

- 派发子代理前必须告知用户：在做什么、为什么用子代理、预期产出
- 监督 Agent 发现问题时应立即纠正，不等到最后
- 汇总 Agent 负责更新任务跟踪文件（task-tracker.md）
