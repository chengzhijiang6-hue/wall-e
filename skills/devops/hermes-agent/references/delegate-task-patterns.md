# Delegate Task 超时与可靠性模式

## 超时问题

delegate_task 默认 600s 超时。以下场景容易超时：

1. **审查任务**：读取 10+ 文件并生成分析报告
2. **大型实施任务**：创建 20+ 文件
3. **网络操作**：需要下载或 API 调用的任务

## 解决方案

### 1. 拆分审查任务
```
# ❌ 错误：一次性审查整个模块
delegate_task("审查 Phase 2 所有代码")

# ✅ 正确：拆分为单文件审查
delegate_task("审查 auth/routes.py")
delegate_task("审查 auth/middleware.py")
```

### 2. 限制文件操作数量
每个子代理任务限制在 10 个文件操作以内。

### 3. 使用 read_file limit 参数
审查大文件时只读取关键部分：
```python
read_file(path="...", limit=50)  # 只读前 50 行
```

### 4. 监督 Agent 只读不写
监督 Agent 只负责读取和分析，不做修改。
修改操作由实施 Agent 执行。

## 中断恢复

如果子代理被中断：
1. 检查已完成的文件操作（API calls 数量）
2. 读取已写入的文件，确认完整性
3. 手动完成剩余部分或重新派发

## 最佳实践

| 任务类型 | 推荐方式 | 预计时间 |
|----------|----------|----------|
| 小型实施（1-5 文件） | 单个子代理 | 60-120s |
| 中型实施（6-15 文件） | 单个子代理 | 120-300s |
| 大型实施（16+ 文件） | 拆分为多个子代理 | 300-600s |
| 代码审查（单文件） | 直接读取 | 30-60s |
| 代码审查（多文件） | 拆分审查 | 每文件 60s |
